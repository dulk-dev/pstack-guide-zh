# 怎样读这本书

## 读者

本书写给已经在用 Cursor、并准备安装 pstack 的人。你需要能读英文标识符。命令、技能名和文件路径保持英文，正文用简体中文说明它们。

如果你只做一件事：安装插件，运行 `/setup-pstack`，然后在需要严格工程工作时使用 `/poteto-mode`。其余技能多半会在剧本步骤里被调用。

## 结构

正文分九部。部的顺序贴近原文 `docs/guide`：先安装，再从 `/poteto-mode` 进入，然后是理解、设计、修复与验证、文字与代码整理、做成自己的方式、自动化，最后是过夜运行和配方。

`poteto-mode` 和 23 个剧本单独成部，因为日常入口在这里，篇幅也最大。23 个原则技能收在设计部，因为模式会在任务开始时读原则索引，其他技能按名字引用它们。

章号由构建程序加上。正文里的交叉引用使用章的 slug，不写死“第几章”。

## 技能节的结构

每个技能是一个二级标题，锚点形如 `#skill-tdd`。标题下一行是原文链接，构建时变成固定提交的 permalink。其后通常是：

1. 一行引用，说明它做什么。
2. 何时使用。
3. 运作方式。
4. 使用例。
5. 陷阱与注意。
6. 相关技能。

剧本的锚点形如 `#playbook-bug-fix`。代理的锚点形如 `#agent-poteto-agent`。

## 原文与本书添加的内容

步骤、触发条件、默认模型和文件路径来自英文原文。本书用自己的话重述，不把韩文指南译过来。

两种添加内容必须带标签，并且标签独占引用块的第一行：

> **示例（本书作者所写，原文中没有）**
>
> 这是为了演示调用方式而写的提示。原文的 README 若已有例子，本书会标明那是原文例子，不再套这个标签。

> **解说（本书的解释，原文中没有）**
>
> 这是原文没有直接写出的推断。它不能压过原文。

没有这两种标签的段落，应当能在固定提交的文件里找到依据。

## 标示

- 反引号里的英文是标识符，不要翻译：`/poteto-mode`、`principle-laziness-protocol`、`subagent_type`。
- `{{src:skills/how/SKILL.md}}` 这种宏只出现在稿件里，构建后变成链接。
- 中文词若不是一对一对应某个英文术语，第一次出现时写成 `原则(principle)` 这种无空格形式。哪些词需要并记，见[术语表](glossary.md#terms-not-one-to-one)。
- 正文不用 U+2014 破折号。

## 阅读顺序

第一次按目录顺序读。之后可以按任务跳转。

| 你要做的事 | 先读 |
| --- | --- |
| 安装并选模型 | [安装与第一次使用](setup.md) |
| 把一件具体工作交给代理 | [poteto-mode](poteto-mode.md) |
| 先弄清代码再改 | [how](how.md)、[why](why.md) |
| 改动会越过函数边界 | [architect](architect.md) |
| 用原则名字把代理拉回来 | [23 个原则技能](principles.md) |
| 过夜后仍要能审计 | [过夜运行](overnight.md) |

选哪个技能，也可以直接看[技能选择流程](decision-flow.md)。全部名称见[技能速查表](quickref.md)。
